РАССЛЕДОВАНИЕ ИНЦИДЕНТА БЕЗОПАСНОСТИ В LINUX

О проекте
- Учебный проект по моделированию и расследованию инцидента безопасности в изолированной среде (Simply Linux VM). Целью было отработать практические навыки реагирования на инциденты (Incident Response) - от обнаружения аномалий до сбора доказательств и составления отчета.

Сценарий инцидента.
В системе обнаружены признаки несанкционированной активности:
- множественные неудачные попытки SSH-подключений с localhost,
- наличие подозрительного скрытого файла в директории /tmp,
- аномальные права доступа к системным файлам.

Ход расследования
1. Обнаружение аномалий
- Множественные неудачные попытки SSH-входа с адреса 127.0.0.1
- Необычно частая перезагрузка системы
- Нарушения в последовательности временных меток

2. Поиск артефактов
- Файл: /tmp/.hidden_system_file
- Права доступа: -rwxrwxrwx (0777)
- Владелец: root

3. Сбор и документирование доказательств
- Логи аутентификации (успешные и неудачные входы)
- Права доступа подозрительного файла
- История выполненных команд в терминале
- Временные метки всех событий

4. Анализ и выводы
- Атака осуществлялась изнутри системы (инсайдерская угроза)
- Файл в /tmp мог использоваться для хранения данных или как бэкдор
- Права 0777 на системном файле являются критическим нарушением безопасности
- Обнаружены проблемы с синхронизацией системного времени

Использованные команды в терминале:
- last - просмотр успешных входов в систему
- lastb - просмотр неудачных попыток входа
- ls -la - детальный список файлов с правами доступа
- history - просмотр истории команд
- ssh - подключение по SSH
- sudo - выполнение команд с правами суперпользователя
- cat - просмотр содержимого файлов
- chmod - изменение прав доступа к файлам
- touch - создание файлов

Логи и системные файлы:
- /var/log/wtmp - логи успешных входов
- /var/log/btmp - логи неудачных попыток входа
- /tmp/ - временная директория (место обнаружения артефакта)

Немедленное реагирование на инцидент:
1. Удалить файл /tmp/.hidden_system_file
2. Сменить пароль учетной записи vikktor
3. Проверить crontab и автозагрузку пользователя

Долгосрочные улучшения:
1. Внедрить систему аудита (auditd)
2. Настроить ограничение прав для пользователей
3. Реализовать регулярный обзор логов безопасности

Методологические навыки:
1. Системный подход к расследованию
2. Документирование каждого этапа работы
3. Сбор и сохранение доказательств
4. Формулирование выводов и рекомендаций

Особенности реализации
1. Данный проект выполнен в учебных целях в изолированной виртуальной среде. Некоторые действия (например, создание файла /tmp/.hidden_system_file) были выполнены для демонстрации возможных методов атаки и соответствующих методов защиты.
2. Проект служит примером практического применения знаний в области кибербезопасности и может быть использован как основа для более сложных сценариев расследования инцидентов.
